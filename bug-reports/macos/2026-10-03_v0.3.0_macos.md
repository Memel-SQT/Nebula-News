## Synthèse

| # | Gravité | Problème |
|---|---|---|
| 1 | **Bloquant** | L'app Mac ne s'ouvre jamais : le serveur Next (`standalone/`) est copié hors du bundle `.app` |
| 2 | **Élevée** | Si le serveur ne démarre pas, l'app reste un processus fantôme sans fenêtre ni message (rejet de promesse non géré) |
| 3 | Moyenne | Fermer la fenêtre sur macOS laisse l'app tourner sans moyen de la rouvrir (pas de handler `activate`) |
| 4 | Faible | Au premier lancement, l'accueil affiche « 0 articles » et ne se rafraîchit pas après la première ingestion |

Ce qui fonctionne : `typecheck` OK, `npm test` OK, build OK. **Une fois le bug 1 contourné** (voir plus bas), le serveur Next démarre en 134 ms, l'UI s'affiche, `/api/ingest` répond 200 (10 sources traitées, 242 éléments récupérés) et `/api/articles` renvoie bien les articles.

## 1. Bloquant — `standalone/` copié hors du bundle `.app`

**Symptôme.** Au lancement, aucune fenêtre. Après 30 s :

```
(node:…) UnhandledPromiseRejectionWarning: Error: Nebula News server did not start within 30000ms
    at Socket.<anonymous> (…/Contents/Resources/app.asar/desktop/main.js:56:18)
```

Lancer le serveur à la main confirme la cause :

```
$ ELECTRON_RUN_AS_NODE=1 "Nebula News.app/Contents/MacOS/Nebula News" "Nebula News.app/Contents/Resources/standalone/server.js"
Error: Cannot find module '…/Nebula News.app/Contents/Resources/standalone/server.js'
```

**Cause.** `scripts/after-pack.cjs` :

```js
const dest = path.join(context.appOutDir, "resources", "standalone");
```

C'est le bon chemin sous Windows/Linux (`<appOutDir>/resources`), mais sous macOS `appOutDir` est `dist-desktop/mac-arm64/` et les ressources sont dans `<appOutDir>/Nebula News.app/Contents/Resources`. Journal du build :

```
[after-pack] copied …/.next/standalone -> …/dist-desktop/mac-arm64/resources/standalone
```

Le dossier finit **à côté** du `.app`, il n'est donc ni dans le `.dmg` ni dans le `.zip`, alors que `desktop/main.js:87` cherche `process.resourcesPath/standalone/server.js`.

**Vérification du correctif.** Copier `dist-desktop/mac-arm64/resources/standalone` dans `Nebula News.app/Contents/Resources/` (sur une copie de l'app) suffit : l'app démarre et fonctionne normalement.

**Correctif proposé (sans effet sur Windows) :**

```js
const resourcesDir =
  context.electronPlatformName === "darwin"
    ? path.join(context.appOutDir, `${context.packager.appInfo.productFilename}.app`, "Contents", "Resources")
    : path.join(context.appOutDir, "resources");
const dest = path.join(resourcesDir, "standalone");
```

## 2. Élevée — processus fantôme si le serveur ne démarre pas

`startServer()` rejette après 30 s (`desktop/main.js:56`), mais le rejet n'est pas géré : pas de `dialog.showErrorBox`, pas de `app.quit()`. L'app reste ouverte (icône dans le Dock, processus Electron + GPU vivants) **sans fenêtre et sans message**. Constaté sur macOS ; le code est le même sur toutes les plateformes.

Autre point : `serverProcess.on("exit")` journalise seulement si `code !== 0 && code !== null`, et le message `Cannot find module` de l'enfant n'est pas apparu dans la sortie du parent pendant le test.

**Piste.** `.catch()` sur le démarrage → boîte d'erreur + `app.quit()`, et arrêt de l'attente dès que `serverProcess` se termine.

## 3. Moyenne — fenêtre impossible à rouvrir sur macOS

`desktop/main.js:336` :

```js
if (process.platform !== "darwin") app.quit();
```

Sur macOS, fermer la fenêtre laisse l'app (et le serveur Next) tourner, ce qui est le comportement Mac attendu, mais il n'y a **aucun** `app.on("activate", …)` dans `desktop/main.js`. Cliquer sur l'icône du Dock ne rouvre donc rien ; il faut quitter (Cmd+Q) puis relancer. Déduit du code (aucune occurrence de `activate`).

**Correctif proposé (macOS uniquement) :** `app.on("activate", () => { if (BrowserWindow.getAllWindows().length === 0 && baseUrl) openWindow(); })`.

## 4. Faible — accueil vide au premier lancement

Base modèle sans article ; la première ingestion part 5 s après le démarrage (`scheduleIngestion`). La page affichée avant reste sur « Aucun article… 0 articles au total » jusqu'à une navigation manuelle, alors que `/api/articles` renvoie déjà des articles. Pas propre à macOS. Pendant le test, l'ingestion a renvoyé `sourcesProcessed: 10, sourcesFailed: 4`, probablement côté réseau ou flux.

## Remarques

- `desktop/icon.ico` est la seule icône : sur macOS, electron-builder utilise alors l'icône Electron par défaut (pas d'`.icns` ni de `.png` 512 px).
- Pas de cible `mac` dans `package.json` → `build`.
- Avertissement Node au démarrage du serveur : `DEP0169 url.parse()` (vient d'une dépendance).
